# 行人复核器

2026-11-16。S3 第一版已完成本地预检和正式实验，未通过继续门槛，当前配方暂停。目标是在固定 R 框的情况下，验证原图局部信息能否改善行人候选排序，使固定 Precision 要求下找回更多真行人。当前 R 是诊断权重，源模型 A 的最终验收沿用[规则](../../RULES.md)。

## 候选

固定 R/17（`a_002` 第 80 轮），根据[本地评价身份](../../runs/a_002/train/final_eval/run.json)和[封存清单](../../runs/a_002/train/manifest.json)核对权重、数据和预测文件 SHA。复用 R 保存的 NMS 后输出，对行人取原分数 `≥0.02` 的框；NMS 配方、下限和输出上限按原评价身份。复核器只给这些行人框写入新的排序分数。

候选身份用数据用途、图像 key 和原始预测索引表示，保留原图框坐标、初始分数和图像哈希。同一图保留所有通过候选门槛的行人框，含无行人标注图中的候选。初步核对，`source_train` 有 15,001 个候选，`source_dev` 有 1,880 个，其中后者在 IoU 0.5 下可匹配 361 个行人，在 IoU 0.75 下可匹配 225 个。这是候选覆盖。真值辅助的一对一筛选和 IoU 排序曾在该池得到 AP50 74.5%、AP50:95 43.0%，仅说明框和候选数量留有空间。候选池唯一来源为 R 的[训练预测](../../runs/a_002/train/final_eval/source_train/objects.jsonl.gz)和[开发预测](../../runs/a_002/train/final_eval/source_dev/objects.jsonl.gz)。

## 样本

训练样本及内部验证均来自冻结的 `source_train`。使用已核验标注按图计算候选与行人 GT 的 IoU，匹配复用原生同类一对一逻辑。划分以现有相似场景风险组为单位。按 UTF-8 字符串 `17:<group_id>` 的 SHA-256 升序排列，前 20% 的组（向上取整）用于内部选模，其余用于拟合。同一图和同一组全部进入同一子集，保存分配与支持量。完整 `source_dev` 用于外部开发对照，最终留出范围见项目规则。

| 候选 | 第一版训练用途 |
|---|---|
| IoU≥0.5 的一对一匹配框 | 正样本，监督分数为与被匹配行人 GT 的 IoU，保留 0.5–1.0 范围内的质量差异。 |
| 对所有行人 GT 的最大 IoU<0.30 | 负样本，监督分数为 0，包括与骑行者等其他类重叠的候选和未匹配背景。 |
| 最大行人 IoU 在 [0.30,0.50)，或 IoU≥0.5 但未获得一对一匹配 | 灰区或重复，第一版排除出监督损失。不同标签的高度相似裁剪框可在全候选评价中核查重复或定位问题。 |
| 已识别的漏标、截断和类别边界疑点 | 仅根据训练侧已有证据按图像和候选身份记录，暂不纳入训练损失。冻结标签的修订按数据版本规则另行安排。 |

当前保存输出按上述纯几何规则得到 `source_train` 正样本 3,427、负样本 9,246、灰区 985、重复 1,343，均为划分及疑点排除之前的计数。实际执行时再记录每个子集和最终标签的数量。**内部验证和开发比较均保留完整的 0.02 候选池**，包含未参加拟合的灰区、重复和误报，匹配使用冻结 GT。R 的训练候选来自 R 训练见过的图片，独立于复核器拟合的 `source_dev` 对照才用于判断是否有开发收益。

[训练侧疑点清单](../../configs/rerank.json)从已有 `source_train` 行人预测审核中选取。仅采用同一图像哈希、原图候选间 IoU≥0.75 的对应框，收录疑似漏标、无法确认目标和无匹配 GT 的类别或截断边界，保留旧案例和 R 索引。它们只作为排除监督的证据。

## 模型

从原图以预测框中心为中心将宽高扩为 1.20 倍，越界部分用 RGB 114 填充。等比例缩放并填充到 `96×96`，使用 RGB/255。目标是学习**候选作为行人框的质量**，让贴合的真行人获得较高分，同时降低背景、错类和松框的排序。

第一版只训练一个小 CNN。三层 3×3 Conv-BN-ReLU，步长 2，通道 16/32/64，接自适应池化到 4×4 和单输出线性层。使用 `BCEWithLogitsLoss` 学习上述软目标，sigmoid 值作为复核分数。原 YOLO 分数用于入池和对照，复核分数直接排序。起始配方为 seed 17、AdamW、学习率 0.001、weight decay 0.0001、batch 64、最多 20 轮，已纳入的候选每轮各参与一次。内部验证按满足行人 Precision 门槛时的 Recall 选轮，并列先看 AP50:95，再选较早轮。内部验证全程没有可行精度点时，当前配方结束，按诊断结果记录。

## 对照

主比较用完整 500 张 `source_dev`。对照臂在 **同一个 0.02 候选池**内按 R 原分数排序，复核臂用选定的同一个复核器 checkpoint 重打分。候选身份、边框、图序、类别及一对一匹配实现对齐。AP 使用全候选排序和原 IoU 列表。两臂分别在自身完整 PR 曲线上取满足同一 Precision 门槛的最高 Recall，使用同分整组过滤后再匹配，报告各自阈值和 TP/FP/FN。其他五类原样输出，逐类核对结果，另列 R 完整原评价作参照。

已从保存输出核对同池 R 的行人基准为 **AP50 56.53%、AP75 34.07%、AP50:95 32.36%**；在 Precision≥75% 时为 **232 TP、76 FP、252 FN，Recall 47.93%**。执行时先核对候选身份和复算口径。报告小/细并集及并集外 Recall、匹配迁移与新增错检，配对风险组区间沿用项目规则。同一机器记录额外裁剪和推理开销，保留候选索引和逐框分数便于重算。

## 决策

- **值得继续。** 相对同池 R，在行人 Precision≥75% 时 Recall 至少提高 **2 个百分点**，在当前 484 个 GT 上相当于净多至少 **10 个 TP**。同时 AP50、AP50:95 的点估计至少保持同池 R 水平，AP75、小/细切片及其他类别按[保护规则](../../RULES.md#保护)复核。达到点估计门槛但区间不足以确认方向时，保留为待复验。正式入围和冻结按[选模与证据规则](../../RULES.md#证据)处理。
- **暂停复审。** 没有达到上述召回收益、无法维持 Precision，或出现质量回退时，记录是哪类新增误报抵消了真检出，或是哪类真框被降分。在结果基础上再决定是否有单独的后续改进依据。
- 获准执行后，正式记录沿用 `runs/<实验>/`：输入身份与分组、实际配方、日志、复核器权重和同池对照结果。原图、裁剪和 R 权重只引用源位置，可重建的运行缓存随执行结束清理。

## 本地预检

[入口](../../scripts/rerank.py)按白名单从封存预测生成样本。`preflight` 验证 R、READY、候选快照和原图标注身份，复算同池 R 指标，以原分数作为另一臂核对两臂指标、PR 和逐框变化，并在三个子集分别取 8 个真实裁剪做 CPU 前向。结果如下。

| 用途 | 图像 | 风险组 | 行人候选 | 监督 |
|---|---:|---:|---:|---|
| `source_train` 拟合 | 3,192 | 2,980 | 11,753 | 2,665 正样本、7,285 负样本 |
| `source_train` 内部验证 | 808 | 746 | 3,248 | 完整候选池选轮 |
| `source_dev` 开发对照 | 500 | 466 | 1,880 | 完整候选池比较 |

三者的风险组、图像 key 和 SHA-256 两两交集均为零。9 个对齐的训练侧疑点中，5 个命中拟合集原定负样本。24 个真实裁剪前向通过，真实数据优化步数为 0。R 的同池结果与预登记基线一致，且把 R 原分数送回复核臂时两臂结果相同。[回归测试](../../tests/train/diagnose/test_rerank.py)用合成图执行了一轮训练，验证 loss、选轮、权重重载和同池评估文件。

```powershell
.\.venv-train\Scripts\python.exe -B scripts/rerank.py preflight
```

正式执行时，`train --output runs/<新实验目录> --device cuda:0` 只读取 `source_train`，保存分组、逐轮 loss 和内部验证结果。若 20 轮全程没有满足 Precision 门槛的内部工作点，则保留 `last.pt` 及运行记录。`evaluate --run runs/<实验目录> --device cuda:0` 读取已锁定的 `best.pt`，在完整 `source_dev` 输出候选分数、PR、匹配迁移和配对风险组区间。其他五类沿用原始 R 预测和评价记录。

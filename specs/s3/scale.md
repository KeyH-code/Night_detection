# 行人分辨率

2026-11-16，确认提高有效输入分辨率为 S3 后续行人专项主线。先准备 YOLO11m 整图 960 的尺度适配对照。现阶段正式源模型基线沿用 [RULES.md](../../RULES.md) 的 640 口径。本页登记后续实验方向和准备事项，下一轮执行待安排。

## 依据

固定 R 的三臂对照显示，在相同的 960 输入几何下，直接从原图缩放比先缩到 640 再放大产生更多 NMS 前的贴合框，在同一 Precision 门槛下找回更多行人，小/细行人贡献了主要净增量。直接 960 相对 640 也改善行人 AP75。剩余问题包括行人召回和 AP50 的资格差距，以及三轮车退化。证据与推理口径见[输入尺度对照](../../reports/a.md#输入尺度对照)。

## 下一轮对照

**问题。** 在保留更多原图细节的基础上，960 训练能否进一步改善同精度召回，尤其是小/细行人，并保住其他类别。

- 建议从同一个 R 第 80 轮权重初始化两个微调臂，训练输入分别为 640 和 960。使用冻结 `source_train`、相同采样、种子、优化器、增强参数、有效 batch 与更新预算。两臂按相同规则建立新的优化器状态。预算和有效参数在预检后登记。
- 固定 R 在 640 和 960 的已有结果为推理参考。两份微调权重各自在同一 `source_dev` 上做 640 和 960 评价，共四个训练尺度与推理尺度组合。机制比较使用同一更新步数的 checkpoint，候选选模和资格另按 [RULES.md](../../RULES.md) 留存。
- 在 960 推理列比较两个微调臂，并查看这份差异在 640 推理列是否同样出现。960 训练的额外收益若主要出现在 960 推理，支持尺度适配。若 640 微调在 960 上也得到类似收益，则补训本身仍是可行解释。

## 行人专项

1. 主指标沿用行人 Precision≥75% 时的最高 Recall，记录阈值、TP/FP/FN 与配对风险组区间。小/细并集按原图面积及固定 640 参考尺度定义，报告并集内外的召回和逐目标迁移。
2. 同时记录 NMS 前通过同一分数地板的 IoU≥0.75 候选覆盖、最终严格匹配数量、AP50、AP75 和 AP50:95。若覆盖改善而工作点收益有限，优先追踪贴合框被哪些高分松框或误报压过。
3. 按既有规则检查其他类别，单列三轮车的实例数、匹配迁移与区间。若收获集中在小/细行人且其他类别通过保护，再评估整图 960 的延迟、显存和正式比较口径。切片推理、P2 和 CNN 复核器留作后续可独立比较的候选方向。

## 准备

- 从已完成的三臂记录核对 R、READY、图像顺序、640/960 输出参数和统计实现，复用有效证据。
- 先确定 960 的显存可行 batch，在 640/960 间对齐微批、梯度累积、有效更新数和学习率日程，保存预检和实测吞吐。正式数据仍由冻结白名单提供。
- 单独登记新实验配方、实际输入尺寸与评价身份，明确运行预算、checkpoint 轮次以及继续与停止条件。数值继续门槛和六类保护引用 [RULES.md](../../RULES.md#停止)，结果留在 `runs/`，结论归[源模型报告](../../reports/a.md)。

## 固定权重尺度筛查

2026-11-19，目标是让行人在同一模型输出上达到 AP50≥70%、AP50:95≥40%、Precision≥75% 时 Recall≥60%，且原已达标的骑行者、汽车、卡车和有轨车辆维持各自完整门槛与 AP 保护线。仍以 [RULES.md](../../RULES.md) 为准；本节是源域开发实验，不更新正式 640 口径，也不以开发筛查替代冻结或终评。

| 实验 | 设计及决策来源 | 云端 GPU 预算 |
|---|---|---|
| 固定权重尺度 | 用 `a_001 best` 和 R80 两个既有权重，各自固定其余设定，比较 640、960、1280、1600、1920 原图直缩。既有[等几何对照](../../reports/a.md#输入尺度对照)支持原图信息量是可控因素；[8 轮复验](../../runs/scale_002/comparison.json)与[24 轮对照](../../runs/scale_003/comparison.json)不支持继续同配方微调。640 用作重放锚点，每格完整 500 图，保留原生 AP 校验、工作点、小/细切片和输出上限。 | 0 小时／0 元；本机单卡顺序跑，较大尺度若显存不可承受，不静默降精度。 |
| 单权重分流 | 对每个 checkpoint 分开检查：其他五类取其 640 原生输出，行人取同一权重的较高尺度输出。不用不同权重拼类；优先保证 `a_001 best` 已达标四类逐框、分数和指标严格不变。合并后仍限制每图 300 框，优先原样保留五类，再按行人分数留满剩余槽位并标出截断；不在此步改全局 NMS。依据是全类同时放大曾损害三轮车，同时固定 640 的旧基线已过四类检查。 | 0 小时／0 元；复用本机缓存预测，仅离线分析。 |

使用核验的 `source_dev`，不访问最终留出或夜间数据。临时实现及未定案的大体积输出只放 `D:\Temp`；实际形成可复查证据后，归同类 `runs/scale_<编号>/`，阶段性决策写源模型报告。若任一点过线，先复核框级保护、风险组区间和同一开发集筛查偏差，再决定后续确认方式；未过线先看定位和评分/误报分别还差多少，不按最高 AP75 选成正式 A。

### 候选融合备选

若前两项都不能同时达到行人门槛和四类保护，追加一次同权重行人融合。已有结果表明用低信息量的 640 分数作为近阈值硬滤器区分能力不足，故不复用该规则。改用 `960/1280/1600` 三个原图直缩视图，仅合并行人：一臂按最高候选分做类内 NMS 保留单尺度发现，另一臂以 IoU≥0.55 归并、每尺度最多一票、缺失计零、按分数加权取框，比较一致性是否改善排序。固定两种规则，不在开发集网格搜索。其余五类仍按同一 checkpoint 的 640 原生输出保留；仍逐图核对并记录输出上限。**云端 GPU 预算 0 小时／0 元**，重用尺度筛查已保存的预测，无额外前向或训练。

若三尺度融合仍不过线，测试更少尺度但增加镜像复验。第一批 `a_001` 重放在 960、1280 的工作点有互补：后者独有 22 名小/细行人、前者独有 32 名非小/细行人；1600 的全体召回更低。因此固定只用 `a_001 best` 的 960 与 1280，比较两路直缩共识和同尺度各增加一路水平翻转的四路共识，沿用上段融合规则。翻转输出必须映回原坐标才评价；其余五类保持 640 原生输出。**云端 GPU 预算 0 小时／0 元**，本机新增两次 500 图前向，无梯度更新；不按结果扩搜翻转/尺寸组合。

尺度筛查完成后补记：R80@640 的卡车 AP50:95 未过保护线，R80@960 的原生四类均满足门槛。因此 R80 三尺度融合保留其 **960** 非行人输出，与 R80@960 比较，不把 640 的已知卡车缺口带入。`a_001 best` 四类仍固定 640。此项只使用筛查已有的 R80 输出，云预算不变；这是同一权重分流，不是按类别拼 checkpoint。

### 原图复现

以 [`person_fusion.py`](../../scripts/person_fusion.py) 从原图和原权重重放。首选 `a1`：四个行人视图为 960、1280 的原图和镜像，非行人只用原生 640；备用 `r80`：行人使用三个直缩视图，非行人用原生 960。两项由同一融合算法实现，视图、权重、数据和输出上限不允许调用时改写。逐图验证非行人框与分数，逐类验证工作点，重新计算完整 AP 与 2,000 次风险组区间；**云端 GPU 预算 0 小时／0 元**。封存用新的输出目录，不覆盖 `scale_004`。

```powershell
.\.venv-train\Scripts\python.exe -B -u scripts/person_fusion.py --profile a1 --scratch D:\Temp --output runs/<新实验目录>
```

这里复现的是开发候选，不是部署验收命令。若同一开发集过线，仍需报告筛查偏差和推理成本，并另定正式的输入/融合协议和确认数据；不改现行 640 资格说明，不启动 S4 或夜间实验。
